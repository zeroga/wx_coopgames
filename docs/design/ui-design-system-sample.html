03 / AW 车辆卡片

K-02-AW · KR-01–09 · PL-01–03

这里是本次确认的核心。切换容器、场景和内容长度，核对车名信息区固定、标签第二排溢出才折叠，以及规划明细与玩家色徽标互斥。

资料库 / 车队总览

示例车辆 · 资料字段与规划分层

实际标签容器 W 用当前 rpx 单位计算。主区档位 448 / 320 / 256 / 192rpx；车型 84rpx，右槽 132rpx，两处间距各 20rpx。W ≥ 560rpx 用规划明细，低于阈值用摘要；这与主区档位是两条规则。

主区固定与两排标签

车名、来源、能力标签共用同一宽度。车型长度和规划人数不会重新挤压主区。第一排尽量装满；两排仍装不下才在第二排放 +N。

正常标签完整显示。单枚超长可省略，点击整个标签区可查看全部完整文字。测量用标签本身宽度，不能拉伸为最长标签宽度。

详情与摘要互斥

详情列出玩家、车辆状态、职责与进度。摘要按玩家 + 职责级别合并，最多两枚；同一玩家的多个级别必须一起显示或一起折叠。

+N人统计隐藏玩家，不统计职责数。未分配职责的规划也必须可达。玩家 / 职责页面只显示当前作用域信息。

    09 / 确认与审查边界

    v2.2 变更 / A · B · C

    本版已确认的规则

    本地勾选用于后续复核，不改变规范确认状态，也不会发送任何数据。

    分类如何判定处理方式
    A · 规范缺口旧规则缺条件或未确认，如两排标签与规划互斥。先补文档和样板，再确认实施。
    B · 实现偏离已有明确标准，实现不一致。修实现，注明规则与提交。
    C · 应用不当组件本身有效，组合或优先级不合理。修场景，补充使用条件。

    旧审查不直接等于当前缺陷。此处是审查分类示范，不是重新宣布当前版本存在整批违规。
