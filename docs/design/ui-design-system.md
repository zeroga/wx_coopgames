# 微信小程序 UI 设计标准

状态：**当前实现基线**  
确认日期：2026-10-05  
适用范围：SnowRunner、Armored Warfare，以及后续接入的小程序游戏模块。

> 本文件定义 UI 规则；具体视觉形态同时以配套 [HTML 样板](./ui-design-system-sample.html) 为实现参考。涉及组件尺寸、密度、相对位置、换行/省略行为时，不能只依据文字描述重新设计。具体小程序代码由后续开发任务按本标准调整。

## 1. 总体原则

1. 设计语言以 SnowRunner 已确认的紧凑、低装饰、浅灰页面 + 白色卡片体系为基础。
2. **K-02 + KR 是核心设计语言。** 任何需要同时表达“主分类、标题、次信息、标签、右侧强调信息”的对象卡，优先使用这套结构。
3. 不为了触摸面积直接撑高可见组件。可见高度与点击命中区分离；命中区可以扩大，但不参与页面布局。
4. 不允许页面各自重新定义同一种按钮、卡片、标签或输入框高度。公共组件先确定语义，再复用统一视觉。
5. 游戏内已有颜色/图标语义优先于全局 UI 语义，但只在对应游戏模块内生效。
6. 新场景没有标准时，先补设计标准再实现，避免实现代码自行“合理化”出新的视觉语言。
7. Markdown 规则与 HTML 样板是一套基线：规则负责语义与约束，样板负责具体视觉参照。若两者冲突或样板未覆盖，不要自行折中，先更新设计资料。
8. **所有可见信息和操作都必须有明确的视觉容器。** 页面背景只负责分隔容器，不能直接承载悬空的标题、统计、说明、链接或操作。一个相关内容组使用一个容器，不要求每行各套一张卡。

## 2. 基础视觉

### 2.1 全局颜色

| 编号 | 用途 | 值 |
|---|---|---|
| C-01 | 主文字 / 深色主操作 | `#1c1a1e` |
| C-02 | 主强调橙 | `#ea7428` |
| C-04 | 完成 / 成功主绿 | `#0c7156` |
| C-05 | 同步成功提示绿 | `#58ba9b` |
| C-06 | 危险 / 删除红 | `#cf3a36` |
| C-07 | 次级文字 | `#6b6370` |
| C-08 | 浅灰控件底 | `#ece9ed` |
| C-09 | 页面背景 | `#f1f0f2` |
| C-10 | 卡片背景 | `#fbfafc` |

卡片基础边框：

```css
border: 1rpx solid rgba(28,26,30,.12);
```

卡片基础阴影：

```css
box-shadow: 0 8rpx 26rpx rgba(28,26,30,.05);
```

### 2.2 页面和卡片

- 普通页面：`padding: 28rpx 24rpx 80rpx`
- 首页：`padding: 44rpx 30rpx 80rpx`
- 普通卡片圆角：`22rpx`
- 普通卡片间距：`18rpx`
- SnowRunner 推进卡：`25rpx` 内边距、`20rpx` 卡间距
- 同组条目可使用浅色虚线分隔；目录 / 设置型列表使用浅色实线分隔

### 2.3 字体层级

保持现有 SnowRunner 层级：

- 首页大标题：约 `52rpx / 800`
- 页面主标题：约 `48rpx / 900`
- 内容卡主标题：约 `34rpx / 900`
- 常规正文 / 输入：`25–28rpx`
- 辅助信息：`20–23rpx`

不要为不同页面随意创建相近但不一致的字号。

## 3. 操作控件

### 3.1 B-01B 普通按钮

普通按钮统一采用：

```css
font-size: 26rpx;
line-height: 1;
padding: 18rpx 26rpx;
border-radius: 14rpx;
min-height: none;
```

规则：

- 主按钮：深色背景 + 白字
- 次按钮：白底 + 浅边框
- 危险按钮：白底 + 红字 + 浅红边框
- 禁用态只降低可用感，不改变组件尺寸
- **不要设置统一的 44px 可见 min-height**

### 3.2 按钮宽度 BW

按钮自身不默认 `width:100%`。

- BW-01：自然宽，用于工具栏、小动作
- BW-02：同组等分，例如“取消 / 保存”
- BW-03：单一主操作可整行满宽
- BW-04：同一操作组可做三等分，例如“复制 / 刷新 / 切换”

宽度由父容器决定。

### 3.3 紧凑按钮 BC

刷新、复制、收起、卡片内次级操作可使用比 B-01B 小一档的紧凑按钮。紧凑按钮不能反向撑高卡片。

### 3.4 图标操作 IC

- 编辑固定使用 **笔形图标**。
- 删除使用统一删除图标。
- 配置使用统一设置/配置图标。
- 上移/下移使用统一方向图标。
- 图标类操作必须来自统一 SVG / 图标组件。
- **禁止随意用“编辑”“×”“!”等文本冒充 icon。**
- 如果操作本来就是文本操作，应作为文本按钮显示，不要伪装成图标。
- 图标可见盒保持紧凑，透明命中区可以向外扩展，但不得改变布局尺寸。

### 3.5 页签 TB / 分段选择 SG

- 页签沿用 SnowRunner 紧凑风格：浅灰容器、白色激活项、轻阴影。
- 不给页签额外增加 44px 可见最低高度。
- 创建人 / 成员等紧凑选择使用分段结构。
- 标签式选择用于职责、状态、筛选等离散选项。

## 4. 输入控件

建议保留三档输入密度：

- I-01 普通表单 / 合作码：约 `88rpx`
- I-02 成员名 / Picker / 搜索：约 `72rpx`
- I-03 行内任务编辑：约 `62rpx`
- 多行备注：最低约 `104rpx`

搜索框和数值筛选不要无条件使用 88rpx 大输入框，应优先使用 I-02 密度。

表单字段 FL 必须区分：

- Label
- 必填标记
- 帮助说明
- 错误说明

帮助文字和错误文字不能混成同一种提示。

---

## 5. 多色语义标签 TAG

标签是全局组件，尺寸、内边距、圆角统一，只通过颜色表达语义。

至少包含：

- 中性属性
- 强调
- 完成 / 成功
- 警告 / 需处理
- 危险 / 错误
- 信息
- 自定义 / 特殊
- 游戏模块扩展

原 CP-01 / CP-02 不再作为独立组件，统一归入多色标签体系。

注意：

- AW 后续需要按这套体系重新梳理现有标签颜色。
- 真正属于游戏内固定语义的颜色（例如 AW 弹种）不受全局标签颜色覆盖。

## 6. K-02 + KR：核心对象卡

这是当前设计语言的核心组件。

### 6.1 信息槽位

K-02 固定的是**信息层级**，不是固定字段。

推荐槽位：

1. 左侧主标识
2. 主标题
3. 次信息行
4. 标签行
5. 右侧强调区

示例：

- 左侧主标识：`MBT`
- 主标题：`M1A2C`
- 次信息：`[T10] 美国 · 经销商名称`
- 标签：`ERA / APS / 烟幕`
- 右侧强调：`主力`、`2/4`、`需前置`、配置入口等

右侧强调内容可以根据业务自由变化，不绑定固定字段。

### 6.1A AW 车辆身份卡

AW 没有可靠的游戏内车型图标时，左侧只用 `MBT / AFV` 等车型文字。使用次级但可辨认的灰紫色（建议 `#aaa2ae`），不能淡到接近卡片底色。

车辆等级放在右侧强调区，`T10` 文字高度接近主标题字号，细边框盒整体高度约 `38rpx`，不再作为高于标题的醒目大块。右侧还可显示多名玩家的规划徽标：每名玩家各占一枚身份色标签，文字明确写主力、备选或手动过渡。成员身份色只表示玩家，徽标文字表示职责级别。已拥有而未规划职责不制造玩家规划徽标。

右侧等级和玩家徽标始终属于同一强调区，不能挤断标题骨架；详细的玩家姓名、状态和配置入口放在卡片下方的同一容器内。

### 6.2 KR 溢出规则

**卡片保持单行骨架，右侧强调区永不下沉。**

空间不足时：

- 优先压缩中间主内容区
- 标题：单行省略号
- 次信息：单行省略号
- 标签：只能完整显示
- 放不下的标签整枚隐藏
- 如果存在隐藏标签，在标签行末显示独立的 `…`
- 禁止出现半个标签、截断标签文字
- 右侧强调内容保持原位

响应式判断优先依据**组件实际容器宽度**，不要只依据 viewport。

## 7. 卡片与列表

### 7.1 K-01 基础卡片

白色卡片、22rpx 圆角、浅边框、轻阴影。

### 7.2 K-05 警告卡

用于需要前置、Token 缺口、数据风险等需要用户注意但并非系统错误的内容。

### 7.3 K-06 导航卡

用于模块入口、功能入口、详情跳转：

- 标题
- 辅助说明
- 右侧导航箭头

### 7.4 列表

- L-01：任务 / 编辑行
- L-03：目录 / 设置行
- L-04：同组内容虚线分隔
- L-05：目录 / 设置实线分隔

### 7.5 CT-01 内容归属容器

- 页面标题使用已有深色 Header；其余独立内容组使用 K-01 卡、K-05 状态卡、K-06 导航卡、表单 Sheet 或有可见边界的标签栏 / 工具栏。
- 标题、辅助说明、统计和本组操作归入同一个容器。成员详情的姓名、改名操作和车辆计数属于一张成员信息卡；车辆本身各自是 K-02 卡。
- 搜索框、筛选入口、已选条件和结果数作为一个筛选工具组。列表下的提示、空状态、加载更多作为相应列表的容器内容或独立状态卡。
- 返回模块入口、版本信息和单独的功能入口使用导航/信息卡，不直接放在页面背景上。
- 容器可以嵌套，但内层车辆卡与外层分组卡之间要有明确的层级和紧凑间距；不能用空白代替容器边界。

### 7.6 GL-01 分组列表与无职责收纳

普通职责分组用一张有标题的分组容器承载车辆卡。没有分配职责的车辆（包括自动生成的科技树过渡车）集中在职责列表底部，使用“未定义职责 · N 辆”折叠标题，默认收起；展开后每辆车仍是独立 K-02 卡。**车队总览和成员详情使用同一规则。** 不把未定义职责伪装成某个目标车辆的职责。

## 8. 指标展示 MT

三种都是正式组件，按**数据量和目的**选择。

### MT-01：少量指标

用于 **2–3 个数据项**。

适合：

- 少量核心指标
- 需要快速比较、较强视觉强调

不是例外样式。

### MT-02：常规单列键值

用于指标较多的常规信息：

```
穿深        800 mm
装填          6.2 s
```

常规性能、武器参数、获取信息等优先使用 MT-02。

### MT-03：两列键值

数据较多且横向空间足够时，将 MT-02 分成两列。

每列内部仍然是“左标签 / 右数值”的 MT-02 结构，不改成大数字卡。

窄容器自动回落成单列。

---

## 9. WA-01：多级列表 / 嵌套选项

WA-01 是**全局结构组件**，不是 AW 专属。

用于：

- AW：武器 → 弹药 → 参数
- SnowRunner：变速箱 → 可选择型号 → 参数
- 后续 WOWS：舰船模块 → 可选模块 → 参数

层级：

1. 一级对象 / 分组标题
2. 二级可选项 / 子项
3. 展开后的三级参数、说明或进一步配置

统一的是：

- 层级
- 缩进
- 容器关系
- 展开 / 收起方式
- 文本与标签排列

游戏模块可以覆盖二级项目的语义颜色，但不能改变 WA-01 的基本层级结构。

---

## 10. Accordion 折叠内容

AC-01 / AC-02 / AC-03：

- 标题区保持稳定高度
- 展开 / 收起入口固定在标题右侧
- 展开内容从明确分隔线后开始
- 展开内容较少时可减少 body padding
- 不因为内容展开改变标题区内部对齐

用于车辆详情的性能、武器、能力、配件、获取、装甲、来源等分区。

## 11. 全局状态与反馈

### 11.1 完成态

“完成 / 已满足 / 已拥有”等属于**全局状态语义**，统一使用完成/成功绿色体系。

SnowRunner 的 `COMPLETE` 印章只是一个具体表现变体，不代表完成态只属于 SnowRunner。

### 11.2 警告和错误必须分开

- 警告：黄色/暖色，用于需要处理、前置不足、数据不完整
- 错误：红色，用于保存失败、同步失败、校验失败

不能继续用同一个 `.warning` 样式包办全部异常。

### 11.3 轻反馈

- Toast：短时成功/操作反馈
- Empty：无数据状态
- LS-01：正在加载
- LS-02：已到底
- LS-03：加载失败 + 重试
- LS-04：手动加载更多

无限滚动和“加载更多”是两种模式，不在同一个列表混用。

### 11.4 Pagination

分页是条件组件，仅管理类或明确需要页码的场景使用。

左右按钮和中间页码标签保持统一视觉高度与垂直居中。

### 11.5 TBAR-01 列表工具栏和状态

搜索、筛选、已选条件及结果计数归入同一工具容器；返回历史的操作可作为有边界的紧凑按钮。列表为空时在列表区域显示有边界的 Empty 容器；分页或继续加载位于列表末端的有边界状态区。不能让标题、计数、帮助说明或加载文字单独漂浮在页面背景上。

## 12. 成员身份色

成员身份色属于**全局识别体系**，不是 SnowRunner 专属。

第一版至少支持 5 个易区分的成员颜色。当前默认色板可使用：

1. `#d96b27`
2. `#663171`
3. `#3f6fb5`
4. `#2d8e91`
5. `#b4567a`

用途：

- 成员标签
- 头像占位
- 车辆 / 任务归属
- 计划归属
- 团队内身份快速识别

成员色只回答“是谁”，不能拿来表达成功、警告、危险等状态。

后续增加小功能：允许用户修改成员配色，优先从预设色板中选择。

## 13. Sheet / Dialog / 排序

### 13.1 SH 底部 Sheet

复杂编辑 / 筛选：

- 固定 Header
- 中间内容独立滚动
- 固定 Footer 主操作
- 统一处理底部安全区
- 键盘弹出时调整可滚动内容，不破坏 Header / Footer

简短选择可使用无固定 Footer 的短 Sheet。

### 13.2 DG 确认 Dialog

以下行为需要二次确认：

- 不可逆删除
- 会影响关联数据的删除
- 退出共享关系
- 覆盖云端等高风险操作

普通草稿项移除不必机械增加确认弹窗。

### 13.3 DR 拖拽 / 排序

优先拖拽柄排序。

如设备或操作环境不方便拖拽，可提供辅助上移 / 下移按钮。

## 14. Sticky 与响应式

### 14.1 Sticky

- 顶部页签可 Sticky
- 底部主操作可 Sticky
- 固定区不能通过额外高度改变原页面密度
- 底部固定区统一处理 safe-area
- 页面内容必须预留对应底部空间

### 14.2 横屏 / 宽容器

响应式优先依据**组件实际容器宽度**。

- 手机：单列
- 中宽容器：允许双栏
- 宽容器：满足最小可用宽度后可增加卡片列数
- 超宽屏内容区应限制最大阅读宽度
- 空间不足应换列 / 回落单列，不允许继续压窄到内容失真

K-02 本身是例外：其内部右侧强调区不下沉，按 KR 规则压缩主内容。

## 15. 游戏模块专属规则

### 15.1 AW SC-01：弹药游戏内语义色

AW 的 AP / HEAT / HE / HESH / 烟幕等颜色必须按 **AW 游戏内既有标识**映射。

该配色：

- 只属于 AW 模块
- 不属于全局品牌色
- 不属于跨游戏标签色
- 不受全局成功 / 警告 / 危险色覆盖

例如 WOWS 中 AP 为红色、HE 为橙色，因此 WOWS 必须建立自己的弹药语义映射，不能继承 AW。

### 15.2 结构与配色分离

AW 武器 / 弹药列表：

- 结构：使用全局 WA-01
- 游戏内弹种配色：使用 AW SC-01

同理，SnowRunner / WOWS 可以复用 WA-01，但各自维护游戏专属颜色。

## 16. 不再作为主标准的历史方案

以下历史样板不应继续影响实现：

- B-01A / B-01C：仅为按钮高度对照；正式采用 B-01B
- OV-03 / OV-04：被 SH / DG 取代
- F-05：被 LS-04 取代
- F-12：被 RS 响应式规则取代
- F-13 / F-14：被 SK Sticky 规则取代
- F-16：被 DG 高风险确认规则取代
- CP-01 / CP-02：已并入多色标签体系
- “SnowRunner 用户 A/B 色是模块专属”这一规则：废止，已提升为全局成员身份色
- “完成态是 SnowRunner 专属”这一规则：废止，已提升为全局完成状态

暂不纳入核心标准：

- Skeleton：当前数据模式没有明确需求，出现真实场景后再设计
- FAB 浮动主操作：当前与底部 Sticky 主操作冲突，暂不采用
- 移动端复杂只读大表：常规参数优先 MT-02 / MT-03；真实需求出现后再设计

## 17. Work 实现时的约束

后续由 Work 调整小程序代码时，应遵循：

1. **不要直接修改业务逻辑来“顺便适配 UI”。** UI 重构和业务改动分开。
2. 先清理重复视觉定义，再统一公共组件。
3. 不得把 `44px min-height` 重新施加到所有可见按钮、页签、标签、图标槽。
