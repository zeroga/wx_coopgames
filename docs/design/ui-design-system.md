## 1. 全局设计原则

1. 采用已确认的浅灰页面、浅白卡片、深色页头、橙色强调；保持紧凑、内容优先、低装饰。
2. 颜色、字号、间距、圆角和状态来自共享 token；页面不得为同一组件重复创造相近尺寸。
3. K-02 固定信息层级，具体字段由模块映射。AW 使用 K-02-AW 的固定槽位变体；不把 AW 字段强塞给其他模块。
4. 可见内容和操作必须归入明确容器。标题、计数、说明、返回入口不能散落在页面背景上。
5. 同组内容共享一张容器；不为了“有容器”让每行再套一层卡片。独立车辆始终各自成卡。
6. 一条信息只选择一个主要表达方式；颜色不能是唯一的信息载体。
7. 小程序本地资料与个人规划状态在界面中分开。资料核验元数据属于后台，个人未完成事项仍可显示。
8. UI 重构不顺便改变研发、Token、权限、存档或同步规则。
9. 默认手机优先，先按实际容器宽度判断可用空间，再决定分栏。禁止只凭“这是 iPad”压缩组件。
10. 样板与文档冲突时先修正设计资料，不允许开发自行折中，也不允许为了迎合偶然实现直接改规范。

## 3. 操作控件 B / BW / BC / IC / HIT

### 3.1 B-01B 普通按钮与宽度

普通按钮：`26rpx` 字号、`line-height:1`、内边距 `18rpx 26rpx`、圆角 `14rpx`。默认自然宽，不设置统一 44px 可见最低高度；文字水平与垂直居中，不继承原生按钮自动外边距或固定宽度。

| 类型 | 表达 | 何时使用 |
|---|---|---|
| 主按钮 | 深色底、白字 | 保存、确认等当前容器的单一主操作 |
| 次按钮 | 白底、浅边框、深色字 | 取消、返回、次级动作 |
| 危险按钮 | 白底、红字、浅红边框 | 删除、退出等危险动作 |
| 紧凑按钮 BC | `23rpx`、内边距 `14rpx 20rpx` | 刷新、复制、收起、工具栏 |
| 轻操作 | `23rpx`、内边距 `8rpx 12rpx`、透明底 | 卡片内次级动作；不冒充主按钮 |

BW-01 自然宽用于工具栏；BW-02 同组等分用于取消 / 保存；BW-03 满宽用于容器内唯一主操作；BW-04 三等分仅用于三个同等优先级动作。宽度由父容器决定，不在每个按钮上无条件写满宽。

### 3.2 交互状态

| 状态 | 视觉与行为 |
|---|---|
| 默认 | 基线尺寸和配色 |
| 按下 | 原地颜色或透明度反馈；不移动周围布局 |
| 选中 | 边框 / 底色变化，并提供文字、勾选或明确状态；不只依赖颜色 |
| 禁用 | 可见区尺寸不变；降低强调且使用真正的 disabled / 不响应事件 |
| 加载 | 说明正在执行，阻止重复请求，保留按钮位置与含义 |
| 键盘焦点 | 样板提供可见焦点；小程序在支持键盘/读屏的平台检查焦点和访问顺序 |

### 3.3 IC 图标操作

编辑用笔，删除用统一删除 SVG，配置用设置/配置 SVG，上下移动用统一方向 SVG，展开用统一 chevron。图标统一描边风格，不用 Emoji、汉字“编辑”、`×`、`!` 或不同字体符号冒充图标。文本按钮仍可显示“关闭”“前置配置”等动作文字。

常规动作图标 `30rpx`，导航箭头 `28rpx`，AW 前置警告图标 `28rpx`。车型没有可信游戏图标时使用 `MBT / LT / TD / AFV / SPG` 文字，不编造图形。

### 3.4 HIT-01 命中区与事件边界

- 保持已确认的紧凑可见尺寸。触摸命中区可以扩大，但必须在所属组件区域内安排，不得覆盖邻近操作、车名或导航区域。
- 小图标优先借用明确的行 / 操作槽。不能用负边距让两个透明点击区域叠在一起。
- 无法安全扩展时改为一个明确的操作组入口，不用误触换取密度。触摸目标大小按小程序实际设备测试，不把 CSS px、rpx、iOS pt、Android dp 当作同一种单位。
- 可用空间允许时，按约 44 CSS px 的独立触摸范围做项目体验检查；这不是所有可见按钮的高度，也不是“当前代码已全部达标”的声明。
- 卡片主体可导航；等级信息、标签详情、规划展开、编辑和配置的内部点击必须停止主体导航。拖拽区与点击区分开。

## 4. 页签、选择和输入 TB / SG / I / FL

TB 页签：灰色组容器、白色激活块、轻阴影，保持紧凑。SG 分段选择用于少量互斥状态；SG 标签式选择用于职责、等级、筛选等离散选项。单选和多选必须在文案或组件状态中可区分。

选择项默认浅灰底，选中用橙色并提供选中状态。可见选择底块与点击外层分离；文字不因选中挤动。长选项自然加宽；超出容器时允许整体换行，不显示半枚选择项。职责的主力 / 备选 / 过渡语义不等于“已拥有 / 计划”资产状态。

| 输入编号 | 场景 | 可见高度 |
|---|---|---|
| I-01 | 合作码、常规表单 | `88rpx` |
| I-02 | 搜索、成员名、Picker、数值筛选 | `72rpx` |
| I-03 | SnowRunner 行内任务编辑 | `62rpx` |
| I-04 | 多行备注 | 至少 `104rpx`，内容 / 键盘按实际场景调整 |

FL 字段应同时支持可见 Label、必要时的必填标记、帮助说明和就近错误说明。Placeholder 不能代替 Label。校验失败保留输入，标出问题字段；不能用同一条灰色文字混写帮助和错误。输入聚焦使用统一边框，错误态采用红色。不得阻止复制粘贴合作码。

### 5.2 ID-C 成员身份色

色板依次为 `#d96b27`、`#663171`、`#3f6fb5`、`#2d8e91`、`#b4567a`。用于成员标签、归属标记、头像占位、玩家规划，不用于表示成功、警告或危险。

正常身份色标签文字选择白字或黑字以满足可读性：当前色板的橙色、青色使用黑字，紫色、蓝色、粉紫色使用白字。同一玩家的身份色必须在同一车队视图内保持一致；当前实现按成员顺序分配，超过五人可复用颜色，因此还必须提供玩家名。未来自选配色是后续功能，不能在样板中误写成现有设置。

## 6. 核心对象卡 K-02 与 AW 固定槽位

### 6.1 全局信息槽位

顺序为：左侧主标识 → 主标题 → 次信息 → 属性标签 → 右侧强调。右侧强调保持其专属槽位，不因中间文本长而掉到整行下面。业务明细与操作放在身份骨架下方的同一张卡里。

普通任务卡、目录对象卡可按业务选择字段；不得把 AW 等级、职责或配色写死进全局 K-02。固定尺寸属于声明过的变体，而不是每个页面自行猜一个值。

### 6.2 K-02-AW 车辆身份骨架

| 槽位 | 普通卡尺寸 | 约束 |
|---|---|---|
| 车型 | 宽 `84rpx`；字 `38rpx / 900` | 所有车型占同一槽位，车名起点一致 |
| 槽间距 | 两处各 `20rpx` | 不随字段长度变化 |
| 车名信息区 | 按下表固定档位 | 整个车名、次信息、能力标签区域使用同一宽度 |
| 右侧等级 / 规划区 | 宽 `132rpx` | 等级和徽标数量不能挤动车名区 |
| 等级 | 高 `44rpx`、字 `32rpx / 900`、最小宽 `60rpx`、水平内边距 `8rpx` | 等级标 `Tn`，传奇用“传奇”，缺失用 `T—` |
| 外部导航箭头 | `28rpx`，与标签组件间距 `8rpx` | 算在外部布局里，不重复占身份骨架宽度 |

设 W 为**车辆标签组件实际可用宽度**，已排除卡片内边距、外部箭头和并列控件，换算为当前 rpx。车型、两处间距和右槽共 `256rpx`。

| W（rpx） | 车名信息区（rpx） |
|---|---|
| `W ≥ 704` | `448` |
| `576 ≤ W < 704` | `320` |
| `512 ≤ W < 576` | `256` |
| `448 ≤ W < 512` | `192` |
| `256 < W < 448` | `floor(W - 256)` 的窄容器回退 |

同一档位的不同车型、长短车名和不同规划人数必须使用相同宽度。剩余空间留在中间与右槽之间，右侧对齐卡片边缘。不能因 Ajax 名称短而缩短主区，也不能因五个徽标而把另一台车主区挤小。

极窄容器无法容纳身份骨架时，应先减少外部并列控件或回落单列，不允许车型、标题、等级互相覆盖。窄容器回退只是一条防溢出规则，不能成为正常页面排版方式。

### 6.3 KR 文字与能力标签溢出

| 编号 | 规则 |
|---|---|
| KR-01 | AW 车名信息区只按容器档位变化，不因车型、名称长度或徽标数变化 |
| KR-02 | 身份骨架不换行，右侧等级槽不下沉；卡片可以向下增长承载两排标签或明细 |
| KR-03 | 标题与次信息单行省略，完整值必须可恢复 |
| KR-04 | 点击等级信息可查看完整车名、车型、等级与来源次信息；不能触发卡片导航 |
| KR-05 | 能力标签按原顺序最多两排；先填第一排，再填第二排；第一排不为 `+N` 预留位置 |
| KR-06 | 一般标签整枚保留，单枚不拆成两行；单枚本身超过整行时才允许单行省略，并可点击查看全部完整标签 |
| KR-07 | 两排放得下全部标签时不显示折叠入口；第二排放不下时，在第二排末显示可点击的 `+N`，N 为隐藏能力标签数 |
| KR-08 | 折叠入口必须留足真实宽度，不能被裁掉，也不能独占错误的一整行宽度 |
| KR-09 | 测量标签和 `+N` 时各自使用自然宽度；隐藏测量列不能把所有元素拉伸到最长标签宽度 |

同组能力标签用 `8rpx` 行内、行间距。标签可见高度 `42rpx`，两排总高 `92rpx`；只有一排时不强行保留第二排空白。点击能力区域或 `+N` 显示完整能力列表，不依赖鼠标悬停。

### 6.4 适用范围

资料库、车队总览、成员车辆、计划步骤、Token 来源和消耗、科技树列表、车辆详情标题、车辆编辑层、前置与 Token 选择层、嵌套过渡目标，全部复用车辆身份组件。英雄标题卡可用 T-05 与深底配色，槽位和溢出规则不另起一套。

## 7. 玩家规划表达 PL：互斥与多人支持

### 7.1 PL-01 展示方式决策

| 情况 | 卡片展示 | 不同时展示的内容 |
|---|---|---|
| 页面已提供玩家获取计划明细，容器可承载 | 玩家名、已拥有 / 计划状态、职责级别、适用的进度 / 目标 / 配置 | 玩家色职责徽标 |
| 资料库 / 总览的窄卡片，无法合理展示明细 | 玩家色职责徽标；多余玩家用 `+N人`，点击展开完整规划 | 下方同一批玩家的明细行 |
| 成员页 / 路线 / 编辑层已有明确玩家或任务上下文 | 保留该上下文的明细与动作，共用车辆身份布局 | 不额外塞入全车队徽标造成重复 |
| 没有任何玩家记录 | 不显示规划徽标或人数 | 不制造“无人规划”的多余标签 |

当前目录 / 总览自动模式：车辆标签容器 `W ≥ 560rpx` 用明细；`W < 560rpx` 用摘要。展示阈值和车名宽度档位是两件不同的事，不能共用同一个条件。业务专用页面可明确选择展示模式，但不能通过取消全部细节来丢掉必要操作。

### 7.2 PL-02 徽标聚合与人数

- 同车允许多名玩家规划；不把同车规划视为冲突。
- 颜色回答“是谁”，文字回答“主力 / 备选 / 过渡”。文字不重复玩家名，但完整规划中必须能看到名字和状态。
- 同一玩家、同一级别、多个职责合并成一枚徽标，完整职责名在展开后保留。
- 已拥有或计划的手动职责均可产生徽标；没有手动职责不制造职责徽标。科技树自动生成的过渡不制造手动规划徽标。
- 紧凑区最多展示两枚徽标；同一玩家的多个级别尽量整体保留，放不下时整组收纳，不能展示半个玩家的级别组。
- `+N人` 是隐藏的独立玩家数量，不是资产数、职责数或徽标数；包括有车辆记录但没有手动职责的玩家。
- 所有玩家都只有未分配职责记录时，可用 `N人规划` 作为入口，展开后注明具体已拥有 / 计划状态，不编造职责。
- 当前职责分组只展示本组职责 / 级别；成员页只展示当前成员；目录按全车队范围。不能把其他分组的路线进度混入本组。

### 7.3 PL-03 明细与展开

完整规划弹层以车辆完整名称为标题，逐名玩家显示：姓名、资产状态、职责、适用的获取进度、过渡目标、自定义前置和前置 / Token 配置入口。明细使用独立滚动内容区，不能因为超过六名玩家而截断记录。

目录明细可先展示两人，再提供“查看其余 N 名玩家”，打开同一个完整规划弹层。摘要模式仍保留自己的编辑入口。配置必须绑定选中的玩家 ID 与车辆 ID；只读队友信息不能获得写权限。

能力折叠的 `+N` 与玩家折叠的 `+N人` 必须分区、分单位。点击任何展开 / 配置动作不触发卡片导航。

## 8. 信息容器、卡片与分组 CT / K / L / GL

| 编号 | 类型 | 使用方式 |
|---|---|---|
| K-01 | 基础信息卡 | 一组相关说明、计数、设置 |
| K-02 | 核心对象卡 | 一个业务对象的身份、属性及明细 |
| K-05 | 警告卡 | 前置不足、Token 缺口等需要处理的个人事项 |
| K-06 | 导航卡 | 模块 / 功能入口，标题、说明、右箭头 |
| L-01 | 任务 / 编辑行 | 保留紧凑行与行内操作 |
| L-03 | 目录 / 设置行 | 使用稳定分隔与导航入口 |
| L-04 | 同组内容虚线 | 同卡明细 / 参数之间 |
| L-05 | 目录 / 设置实线 | 目录型条目之间 |

CT-01：成员姓名、改名与车辆计数归入同一成员信息卡；搜索、筛选入口、已选条件和结果数归入同一工具容器；版本、返回模块、列表说明归入导航 / 信息容器。空状态和加载状态要在所属列表范围内出现，不能作为背景上的孤立文字。

GL-01：职责分组用有标题的分组容器承载独立车辆卡。未定义职责车辆集中在底部，用“未定义职责 · N 辆”默认收起；展开后每辆车独立成卡。总览与成员车辆页使用同一规则。自动过渡车是否归入该组由业务数据决定，不在 UI 中伪造职责。

层级最多表达必要的外层分组 → 独立对象 → 内部明细。相邻车辆不共享模糊边界；每条普通文本明细不再套一张重阴影卡。

## 9. 指标 MT 与多级内容 WA / AC

### 9.1 MT 指标选择

| 类型 | 使用条件 | 结构 |
|---|---|---|
| MT-01 | 2–3 项少量核心指标，需要快速比较 | 小型指标块，不铺成一整页大数字 |
| MT-02 | 普通参数、字段较多 | 单列键值，标签左、数值右，单位与数值一致 |
| MT-03 | 参数较多且每列仍可读 | 两列 MT-02；窄容器回落单列 |

不为每个参数单独造指标卡。未知值明确用缺失表示，不自动填 0。单位来自数据口径，不为排版改变或推测数值。

### 9.2 WA-01 多级列表

一级对象 / 分组 → 二级选项 / 子项 → 三级参数与说明。AW 武器 → 弹药 → 参数、SnowRunner 变速箱 → 型号 → 参数可复用结构；配色由各游戏映射。

一级、二级保持标题和固定展开入口，三级参数通过边界与缩进区分。展开内容较少时减少内边距，不改变标题位置。不能隐藏“互斥武器 / 二选一”的实际关系，也不能把内部 configuration_key 序号展示成用户内容。

### 9.3 AC 折叠分区

AC-01/02/03 用于性能、武器、能力、配件、获取、装甲、来源等内容。标题区稳定，展开入口在右侧，正文从分隔线后出现。车辆基本身份和玩家状态常驻；每枚弹药可独立展开，不要求整页全部同时展开。

## 10. 筛选、导航与结果状态 TBAR / NAV / LS

TBAR-01 把搜索、筛选入口、已选条件、结果计数和资料状态归入一个工具容器。搜索独立成行或使用不受挤压的控件。筛选面板可以再次提供搜索，但必须与列表共享同一值。

- 多选条件用选择标签，不把每个条件都变成下拉框。
- 关闭筛选只收起面板，保留查询；重置清空明确的条件集合。
- 选中条件可逐条取消，整体重置有明确文案。
- 零结果说明减少条件，不伪装成资料加载失败。
- 新模块返回已有页面优先恢复其筛选、选中项和滚动上下文；不能不断堆叠重复页面。

| 编号 | 列表状态 | 呈现 |
|---|---|---|
| LS-01 | 正在加载 | 有范围的状态容器，说明正在获取什么 |
| LS-02 | 已到底 | 列表末端简短说明 |
| LS-03 | 加载失败 | 错误原因摘要与明确重试入口；保留已有列表 |
| LS-04 | 手动加载更多 | 列表尾部按钮 / 状态容器 |
| EMPTY | 无数据 / 零结果 | 区分没有记录、筛选无结果和错误，提供适当下一步 |

同一列表选择无限滚动或手动加载更多之一，不混用。分页仅用于有页码定位需求的管理列表；左右按钮与页码标签高度、基线统一。

## 11. 全局状态与反馈 ST

| 状态 | 语义与处理 |
|---|---|
| 成功 / 已完成 / 已拥有 | 绿色语义；是否显示成功标签由场景决定，不要求每辆已拥有车重复贴绿标签 |
| 前置 / Token 待处理 | 警告语义，用同一个黄色感叹号入口配置；没有配置前置时保留提示 |
| 自定义前置 | 独立紫色标签，不与普通警告混成一个状态 |
| 保存 / 同步 / 校验失败 | 红色错误容器，说明可恢复方式；不复用黄色 `.warning` |
| 轻反馈 | 短时 Toast 表示完成，不代替持久错误和重要状态 |
| 离线 / 缓存 | 清楚区分当前本地内容与刷新状态，不假装已同步 |

不展示后台资料核验标签、纯核验备注、内部配置分组编号。前置未满足、Token 缺口、个人奖励进度属于实际业务状态，继续可见。未知规则不能伪装成已满足。

SnowRunner 的 COMPLETE 印章是全局完成语义的模块表现变体，不把印章造型推广到所有游戏。

## 12. Sheet、Dialog、排序 SH / DG / DR

### 12.1 SH 分型

| 类型 | 内容 | 结构 |
|---|---|---|
| SH-01 编辑 / 配置 | 车辆状态、职责、前置 / Token | 固定 Header、独立滚动 Body、固定 Footer 取消 / 保存 |
| SH-02 筛选 | 多组筛选条件 | 固定标题 / 分类区、滚动条件、重置 / 查看结果 |
| SH-03 只读展开 / 简短选择 | 完整能力、多人规划、短选项 | 清晰标题与关闭，可不设固定 Footer；多人记录仍独立滚动 |

复杂 Sheet 最大高度按可用窗口约 90% 安排；安全区加在底部。已实现的多人规划与筛选可使用约 `55vh` 的内容滚动区，这是相应变体，不强制所有短弹层占同样高度。小程序 scroll-view 的竖向滚动区应有明确高度约束。

键盘出现时调整可用内容高度，标题、关闭和保存保持可到达。关闭只读弹层不修改业务数据；编辑草稿取消不保存。点击遮罩是否关闭必须按类型定义，复杂未保存编辑不能被无提示丢弃。展示层级：页面 → Sticky → 遮罩 → Sheet → 明确的二级 Dialog，不滥用任意高 z-index。

### 12.2 DG 确认与权限

不可逆删除、影响关联数据的删除、退出共享关系、覆盖云端等危险操作需要确认。文案写明对象、影响和动作，默认焦点不放在危险确认上；取消必须有明确出口。业务不允许的操作直接禁用 / 说明原因，不能借“二次确认”放开权限。普通草稿项移除不机械加弹窗。

### 12.3 DR 排序

用独立拖动柄；保留上移 / 下移作为无法拖拽时的替代。第一项不能上移，最后一项不能下移。排序行不因辅助控件挤压名称；空间不足时整组操作换到下一行。排序不要求开发顺便更改数据权限。

## 13. Sticky、响应式与可访问性 SK / RS / A11Y

SK-01 顶部页签可固定；SK-02 单一底部主操作可固定；SK-03 内容必须预留固定区和安全区的对应空间。固定区不通过额外高度改变原页面密度，也不能挡住最后一条内容或输入焦点。

RS：手机默认单列；实际容器可容纳完整组件时才增加列数；超宽屏限制阅读宽度。卡片内部按 K-02-AW 档位调整，外部分栏按最小可用宽度调整，不能用“右槽不下沉”当作把所有卡片压成极窄列的理由。MT-03 不够宽时回落 MT-02。

A11Y 项目规则：

- 控件有可识别名称、选中 / 展开 / 禁用状态；单独图标操作有文字替代。
- 颜色旁保留职责、状态或类型文字。五色不等于能唯一识别任意数量玩家。
- 正文自然换行；必要的单行省略有触摸可用的完整值入口。
- 支持键盘的平台提供可见焦点和合理顺序；关闭展开层后回到触发位置。该交互作为本稿的项目建议，不宣称来自专门的微信原生栈指南。
- 降低动态效果时保留即时状态反馈。动效主要采用颜色 / 透明度，按下反馈可采用约 80–150ms；不强制添加复杂动画或 GSAP。
- 放大文字、窄屏、横屏下不能出现信息永久不可恢复、操作相互覆盖或正文横向滚动。调整密度必须有已声明的变体。
- 当前仅定义浅色页面与深色 Header；完整深色主题不在本稿交付范围内，不能据此宣称已有深色模式。

## 15. 审查分类：规范缺口、实现偏离、应用不当

审查不能把所有建议都写成违规，也不能用“样板没画到”证明代码任意实现都是正确。每条结论要给出：场景、规范版本、规则编号、当前行为、期望行为、对应样板。

| 分类 | 判定 | 本稿中的典型例子 | 后续动作 |
|---|---|---|---|
| A 规范不足 / 需美化 | 原文缺条件、互相矛盾、视觉建议未确定 | 固定车名区档位、两排标签、规划互斥、徽标与玩家计数、单枚超长标签恢复 | 先补规范与样板，用户确认后实施；不能直接认定旧代码违规 |
| B 不符合规范的实现 | 已有明确规则，实现偏离 | 错误用黄色警告、车型图形未经确认、同类按钮各页不同尺寸、纯核验元数据出现在前台 | 修实现，不为代码偏离降低规范 |
| C 规范内不合理应用 | 组件合法但放错场景、优先级或组合 | 很多普通参数都用大指标块、正文每行独立重卡、同时出现明细与同义徽标、把所有操作都当主按钮 | 明确使用条件和组合关系，修所在场景，保留组件本身 |

上述为分类准则和示例，**不是对当前 abb7d91 重新宣布整批违规**。历史审查针对旧提交；已整改内容应标记关闭或留作回归条件，不重复当作新问题。

## 17. Work 实现与验收

### 17.1 变更流程

1. 先确定规范版本、规则编号和参考样板，再改共享组件；页面只映射业务字段。
2. 复用 `utils/ui/components.wxss`、模块 theme、车辆标签等既有来源，避免在四处重复定义同一视觉参数。
3. 不因为 HTML 样板可运行就直接复制浏览器实现替代 WXML / WXSS；原生按钮、SelectorQuery、scroll-view、键盘、安全区必须在小程序中核验。
4. 同一次规范变更，文档、样板、变更表和验收项一起更新；开发变更注明所依据的规范。
5. UI 修改与业务数据、规则、SQL 迁移分开。未确认的新能力保持后续状态。

### 17.2 核心验收矩阵

| 场景 | 必须验证 |
|---|---|
| 320 / 375 / 390px 手机参考 | 无主体横向溢出，固定车名起点 / 档位，等级槽不下沉 |
| 768px 与横屏 / 分栏 | 先验证真实卡片宽度再决定模式，窄列回落，文字有恢复入口 |
| 短车名、长车名、MBT / AFV / SPG、传奇 / 缺失 | 车型槽、主区、右槽一致；缺失不猜测补齐 |
| 0 / 1 / 3 / 多个能力标签 | 无标签不留空区域；第一排优先；第二排才折叠；两排能容纳时无 `+N` |
| 单枚超长能力 | 单行、可恢复全文，其他标签计数正确 |
| 0 / 1 / 多名玩家、同玩家多级别 | 明细与徽标互斥；隐藏按玩家计数；完整层不截断记录 |
| 玩家 / 当前职责作用域 | 不显示其他分组职责和路线进度，不混用玩家 ID |
| 卡片导航 + 内部操作 | 标签、规划、等级、编辑、配置不误触导航 |
| 表单 / 草稿 / 键盘 / 安全区 | 取消不保存、错误保留输入、关闭与保存可达、末行不被盖住 |
| SnowRunner 回归 | 原卡片密度、任务行、归属、勾选、排序、完成态不被 AW 样式撑高 |
| 视觉与语义 | 主次层级明确，颜色不是唯一提示，错误与警告分离，所有内容有容器 |

### 17.3 样板验证范围

配套 HTML 样板通过 34 项浏览器检查（布局、折叠、作用域、弹层与草稿交互），可用于确认组件相对位置、尺寸、换行、折叠、互斥展示和演示交互；不代表已经通过微信真机、键盘、安全区、原生控件或完整辅助技术验收。小程序 2026.10.05.5 的既有 95 项测试与原生编译结果属于代码基线，不能冒充本次新增规范都已实现。
