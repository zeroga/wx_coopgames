## v2.2 · 2026-10-06 · 用户已确认

实现参照：PR #8 / `abb7d919627c016da37c1edafb06fc11fba7a152` / 测试版 `2026.10.05.5`。

配套文件：[规范文档](./ui-design-system.md)、[交互样板](./ui-design-system-sample.html)。本次只更新设计资料，不修改小程序、车辆资料、存档逻辑、数据库或测试版号。

- AW 车辆身份统一固定槽位：车型、车名信息区与右槽固定；主区按真实容器宽度档位计算，应用于所有车辆卡片页面和弹层。
- 能力标签最多两排，先填第一排；第二排不足才出现 `+N`。正常标签整枚显示，单枚超长和完整能力列表可点击恢复。
- 玩家规划明细与玩家色职责徽标互斥。窄卡摘要支持多人；按玩家与级别合并，同玩家多级别整体保留或折叠，隐藏数量按玩家计数。
- 完整补齐 token、按钮、输入、语义标签、容器、参数层级、反馈、弹层、排序替代、响应式与可访问性规则，注明模块专属映射和后续能力边界。
- 区分规范缺口、实现偏离、规范内应用不当；历史审查不得直接当作当前缺陷。
- 更新样板与章节映射，保留演示数据说明、交互作用域和真机验收边界；中文回退字体随样板嵌入，保留 SIL OFL 许可证。

验证：确认稿样板通过 34 项浏览器检查，覆盖 320 / 375 / 390 / 768px、主区一致、两排折叠、多人聚合、作用域、弹层返回、草稿取消和筛选计数。HTML 不代替微信真机、键盘、安全区或原生控件验收。
