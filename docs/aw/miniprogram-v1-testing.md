## 2026.10.04.4 Token 与手机交互更新

- Token 由具体车辆练满经验的一次性奖励产生，由实际解锁路线消耗。取消手填持有量入口，旧 `tokens`、`confirmedRewards` 原样保留供备份，但不再用于新计算。已拥有不等于已领取：车辆编辑和规划来源中可记录“未满经验 / 满经验待领取 / 已领取”；旧车辆缺记录时提示补齐，不推断余额。
- 每类 Token 分别显示已领取、历史消耗、当前可用、本轮需求、奖励上限、按当前顺序可获得量、总量缺口及下一步缺口。合并去重车辆、前置、奖励、消耗；列出具体来源车、消费车、补充来源和建议顺序。补充来源需主动加入练车计划才计入，已解锁但未购买的车辆可记录实际消耗。完整实现说明：[Token 规划](token-planning.md)。
- 顺序计算优先来源和其前置，并在竞争同一 Token 时回溯；后续奖励不能预支。未知路线/消耗会阻断后续收益推断；搜索超过 3000 次会标记待确认，不能据此断言循环或无解。
- 等量 Token 可以支付；此前用户要求的“获取总量严格大于消耗”保留为独立余量检查，不能把等量误报为支付不足。
- 有玩家码或已连接车队时，车辆、备注、名字、奖励进度、实际消耗、路线、条件确认和职责变更保存后自动上传。无玩家码仍保存本地。一个“刷新”入口先上传再下载，失败/冲突停止下载并保留改动；仅有个人码时也支持自动上传、读取更新。同步状态常驻，失败可重试。
- 手机选择尽量直接可见：车辆状态、三种职责等级、奖励进度、实际获取方式及是/否筛选均用橙色选中、灰色未选的按钮；获取路线用带条件的卡片；少量成员按钮、多成员搜索列表。弹药颜色仍沿用已核实的弹头分类。
- 新登记默认“计划”。职责通过标签选中，取消标签即移除手工分配；自动前置明确显示“过渡 · 科技树自动生成”和服务目标。职责管理成为独立编辑子视图，返回保留车辆状态、备注、职责和 Token 草稿。
- 名称输入独占首行；第二行筛选按钮靠左、清空靠右；第三行已选标签自然换行，无条件时隐藏。去掉搜索卡片、重复标签和面板内重复名称输入。筛选分类换行，点击区域增大。

## 数据结构与权限

| 数据 | 玩家存档 AW-M | 车队存档 AW-T |
| --- | --- | --- |
| 名字、已拥有/计划车辆、备注 | 保存 | 通过关联读取 |
| 奖励进度、实际 Token 消耗、来源车计划、路线与条件确认 | 作为资产字段保存 | 获取规划读取 |
| 职责定义及顺序 | — | 共用 |
| 自己的车辆职责、主力/备选/过渡、手工依赖 | — | 保存在各车队；修改需自己的玩家码 |

同一玩家可加入多个车队，个人数据共用，职责各自独立。服务器不会向持车队码的查看者返回玩家码。本机只显示已识别的自己的玩家码。

所有已保存的自己的改动先存本地，有玩家码或车队连接时自动上传；共同职责定义仍归车队，未连接车队时保存在本机。个人档与车队档分别比较版本；一次上传不是跨全部存档的大事务，部分失败保留已成功版本。同步期间阻止编辑/切换；刷新保护未上传内容；放弃本地版本需确认。切换存档保留缓存，读取新车队后需再次输入自己的玩家码。备份包含本机保存的存档码。
