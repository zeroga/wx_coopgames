## 编译阻塞修复（2026-10-03 后续反馈）

上传日志显示资料库 `wx:if` 的 `&lt;` 导致 ``unexpected `;` at pos18``，整个小程序模板编译被阻断。改为原始比较表达式 `count > results.length`，同时修正车队页面两处 `&amp;&amp;` 为 `&&`。

此前 XML 结构检查会自动解码实体，漏掉了微信表达式编译差异。现检查原始绑定，拒绝 XML 实体，仅在结构检查阶段对合法原始运算符转义；回归覆盖分页提示、职责目标与获取条件开关。

额外使用 `miniprogram-compiler@0.2.3` 中的微信 wcc / wcsc 编译器：旧文件复现上传日志的同一编译错误，修复后全小程序 WXML / WXSS 编译通过。该编译依赖仅装在外部构建目录，不增加小程序包或运行依赖。可复查：

```bash
npm install --prefix /path/to/build-tools miniprogram-compiler@0.2.3
node tools/check_aw_compile.js /path/to/build-tools/node_modules/miniprogram-compiler
```

命令行编译通过不等于已完成开发者工具/真机渲染验收。拉取修复后在开发者工具中重新编译即可，无需清除存档或重新执行 SQL。

## 本地运行

1. 拉取 `feat/aw-catalog-fleet-v1`。
2. 保留现有 `project.config.json`。首次导入时复制 `project.config.example.json` 并填写自己的 AppID。
3. 微信开发者工具导入仓库根目录，确认 `miniprogramRoot` 为 `miniprogram/`，启用增强编译。
4. 首页进入 AW 模块入口 → 车辆资料库 / 车队管理。
5. 可以先本地使用。生成成员码、创建或加入车队需要网络。
6. 当前项目数据库接口已经部署，不需再手动运行 SQL。其他项目按文档中的数据库步骤安装。

随包公开资料来自已有手动数据包（2026-10-01），含 298 辆车。资料不足显示待确认，不为演示伪造完整路线。生成文件通过 `python tools/build_aw_miniprogram_catalog.py` 重建。没有车辆图片或新增 npm 依赖；小程序源文件约 1.08 MB。

## 两种存档的关系

| 数据 | 成员存档（AW-M） | 车队存档（AW-T） |
| --- | --- | --- |
| 显示名、已拥有 / 计划车辆、个人备注 | 保存 | 通过成员关联读取 |
| Token 当前持有量、路线选择、条件确认 | 保存 | 获取规划读取 |
| 自定义职责、职责顺序 | — | 保存 |
| 车辆在该车队承担的职责与级别 | — | 保存 |
| 手工过渡目标及依赖 | — | 保存；科技树前置自动重算 |
| 成员停用、顺序 | — | 属于当前车队 |

成员以稳定 ID 关联，改名不改变关系。同一成员可加入多个车队；个人资料共用，各车队的职责互不覆盖。所有前置仍按明确的 `unlock_paths / unlock_requirements` 递归生成；显示关系不用于推断前置。

车队码可查看所关联的个人资料和管理本车队职责，但不能修改个人资料。只有本机已关联成员码时，车辆状态、备注、名字、Token、个人路线和确认条件才可编辑。服务器不把成员码返回给车队查看者。车辆登记弹层只编辑当前自己的成员档，不提供玩家选择；没有个人身份时先建立本地成员档或关联自己的 AW-M 码，持车队码不能直接解锁个人登记。

新建成员先保存本地；“生成成员存档码”发布个人档。创建车队或上传时也会为尚未发布的本地成员生成成员档。生成成功后，以服务器稳定 ID 重映射车辆、职责、目标与个人数据键，不修改用户已有状态。

解除关联仅移除此车队的关联与职责，独立成员档及其他车队关联保留。有未上传个人改动时要求先上传。停用成员保留所有记录。

## 同步与冲突

成员和车队各有独立版本。所有写接口在服务端锁定对应存档并比较 `expected_version`；旧版本写入被拒绝，保留本地改动。成员上传成功而车队上传失败时，保留已成功的成员版本，重试只处理未成功部分。

一次“上传”包含多个独立存档，整体不是跨所有成员的大事务。部分失败会明确提示并可重试。同步期间禁止编辑或切换，取消弹层仍可用。职责或个人数据变更先保存本地，随后手动上传。

“刷新”在存在本地改动时拒绝覆盖；“载入云端”需先确认，用于放弃本地未上传版本。备份包含当前车队、成员资料及本机掌握的存档码。

“切换存档”回到本地车队，原车队缓存保留；再输入另一车队码加入。离线仍可查随包资料和已有缓存。

## 数据库安装与权限

SQL：`supabase/sql/004_aw_member_team_archives.sql`。

新增 `private.aw_member_saves`、`private.aw_team_saves`、`private.aw_team_members`，三表启用 RLS，拒绝 anon / authenticated 直接读写；仅开放 `public.aw_archive`。私有实现函数撤销直接调用权限。输入码只存 SHA-256 哈希，服务器生成128位随机码，类型前缀参与哈希。

本应用沿用无需登录、持码访问的机制，因此统一 RPC 有意使用 SECURITY DEFINER，所有非创建操作严格验证对应类型码，固定空 search_path。安全检查会提示“RLS enabled no policy”和“匿名可执行 SECURITY DEFINER”：这是隔离表、只开放受码验证 RPC 的设计结果，未添加公共读写策略。评审说明见 [匿名 RPC 提示](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable) 和 [无直接表策略提示](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)。

本次已在目标项目部署新结构并验证，SQL重复执行保持幂等。没有改动旧 `coop_profiles / game_states / aw_fleet_plan_items`、旧合作码或公共车辆资料。

## 旧存档过渡

- 原 `aw.v1.<旧profileId或local>` 本地缓存首次读取时复制为 v2 工作数据，原缓存保留，并另存完整旧快照。
- SnowRunner 的合作档和代码保持原样，AW v2 使用独立缓存和码，不再自动共用 SnowRunner 的当前档。
- “导入旧 AW 存档”仅在空白本地车队使用，读取旧 `game_states.aw`；若没有该状态，读取旧计划 RPC。全程不写旧档。
- 旧职责、原始审计、状态、备注保留，不猜测旧角色映射；发布时创建独立成员档和新车队档。
- 不自动把数据库中全部旧档批量搬迁。用户在本地核对后，主动生成成员码或创建新车队。

## 验收清单

1. 初次进入车辆详情不弹出编辑层；点击编辑 → 取消 / 遮罩，应关闭且不保存；已有成员时能看到正确成员表单。

3. 用“ATGM + 攻顶 + 自导 + 穿深”组合检查同一枚弹药约束，测试出厂能力开关和未知资料。
4. 新建成员 → 登记车辆 → 生成 AW-M 码 → 创建 AW-T 车队；重启后成员、车辆、职责、当前成员均保留。
5. 在第二台设备仅输入车队码，个人资料只读，可管理车队职责定义；再输入自己的成员码，自己的车辆登记解锁。
