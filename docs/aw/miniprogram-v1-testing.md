# AW 测试版 2026.10.04（Issue #3 / #5，PR #8）

本版用于外部用户测试。Figma 暂缓，按小程序反馈迭代。PR 与两个 Issue 保持开放；尚未完成微信开发者工具或真机验收。

## 本轮改动记录

| 用户反馈 | 测试版行为 |
| --- | --- |
| 车辆资料先只用本地资源 | 298 辆车及武器、弹药、能力、科技树、获取条件全部读取随包快照；删除“刷新云端资料”、`store.loadCatalog` 和远程资料读取方法。资料页和科技树不请求车辆数据库。玩家/车队存档仍通过 Supabase 同步。 |
| 要收起的是弹药详情 | 展开“武器与弹药”后，列出每个武器及全部弹药。每枚弹药默认一行（彩色弹种、名称、箭头），可单独展开/收起参数、说明、来源；展开后长名称完整显示。武器说明放在该武器弹药列表之后。 |
| 顶部车辆状态、车队状态不要折叠 | 两处常驻，不显示折叠箭头；性能、武器、能力、配件、获取、装甲、来源模块仍独立折叠。 |
| 成员只能定义自己 | 去掉“设为当前玩家”、新建队友、成员停用及成员排序入口。玩家码自动确定自己的身份；队友信息/规划可查看，车辆、名字、Token、路线、确认条件与职责安排只能修改自己。 |
| 读取车队码后输入玩家码 | 先读取 AW-T 车队，再出现 AW-M 玩家码输入。尚未入队弹出确认；取消不建立关联；已入队直接载入资料，不重复关联或增加版本。 |

| 数据库同步调整 | 已部署 `aw_self_membership`：车队职责写入与退出同时验证车队码和玩家码；只能移除自己、修改自己的职责。整队上传保留其他成员的职责/依赖，禁止修改成员列表、停用和顺序。删除被队友使用的职责会被拒绝，需先由队友调整。 |

职责定义仍由车队成员共用，可新增、改名、排序；修改共享标签不能顺带覆盖其他人的车辆职责。车辆登记弹层使用标签多选，分别设置主力/备选/过渡，管理标签时保留车辆草稿。

## 从本地源码上传体验版

1. 拉取分支 `feat/aw-catalog-fleet-v1`，保留自己的 `project.config.json`；首次使用复制 `project.config.example.json` 并填 AppID。
2. 微信开发者工具导入仓库根目录，`miniprogramRoot` 为 `miniprogram/`，启用增强编译并重新编译。无需清空存档或重新导入资料。
3. 首页进入 AW，底部可确认“测试版 2026.10.04 · 车辆资料随包读取”。
4. 先在开发者工具/真机走下面的两设备流程；存档请求域名需配置目标 Supabase 项目的 HTTPS 域名。车辆资料浏览可离线使用。
5. 使用微信开发者工具“上传”，版本号可填 `0.1.0-test.20261004`，备注“AW 本地车辆资料、个人玩家码入队与退出测试”。
6. 在微信小程序后台将上传版本设为体验版，添加体验成员，再分享体验二维码。源码/PR 更新不会自动上传微信体验版。

当前 Supabase 项目已部署 004 和 005 接口，无需手动执行 SQL。旧版客户端没有传入玩家码的车队写入会被新接口拒绝，应重新编译本分支。

## 外部测试步骤

1. **资料浏览**：断网进入资料库，搜索、筛选、翻页、详情、科技树可用；无云端资料刷新按钮。未知数据仍显示待核实，不补造路线。
2. **详情布局**：顶部信息和车队状态常驻；展开武器模块，所有武器及弹药行可见；只点某枚弹药才展开该弹药详情，其他行不变。AP 系蓝色、HEAT 红色、HE 橙色，尚未核实类型保持中性色。
3. **创建个人档与车队**：设备 A 建立自己的玩家档 → 登记车辆/职责 → 生成并复制 AW-M 码 → 创建 AW-T 车队 → 上传。重启后资料和身份保留。创建车队也会自动发布尚未生成码的个人档。
4. **新成员入队**：设备 B 先读取 A 分享的 AW-T 码；此时只读。再输入 B 自己的 AW-M 码（没有码可建立自己的档），出现加入确认；先取消核对未入队，再确认加入。
5. **已有成员读取**：第二台设备输入 AW-T，再输入已经关联的自己的 AW-M，直接读取，不弹加入确认；显示自己的名字、玩家码、退出按钮。
6. **自己与队友权限**：选择队友可查看车辆和规划；没有修改名字、移除车辆、停用、退出队友的按钮。自己的登记、备注、Token、职责可编辑；删除队友正在使用的职责应明确拒绝。
7. **退出**：上传未同步改动 → 退出确认 → 自己从当前车队移除；个人档仍可用原 AW-M 读取，另一车队的关联/职责仍保留。未识别身份时退出按钮隐藏。
8. **双设备冲突**：两台设备载入同版本，先后上传，第二次旧版本被拒绝并保留本地内容；复制备份、确认载入云端后继续。个人上传成功、车队上传失败可重试。
9. **领域规则**：职责标签多选、主力/备选/过渡、手工多目标过渡、全部科技树前置自动生成；Token 总量需严格大于消耗，后续奖励不能支付先前消耗。
10. **手机交互**：取消/遮罩不保存；五类筛选关闭后保留；长弹药名称、键盘、滚动、固定底部按钮、复制码、原生返回和已有页面复用正常。

反馈时附“测试版 2026.10.04”、所在页面、操作步骤、截图/日志；涉及存档的反馈可使用单独的测试车队。车队码用于分享，玩家码由本人保存。

## 数据结构与权限

| 数据 | 玩家存档 AW-M | 车队存档 AW-T |
| --- | --- | --- |
| 名字、已拥有/计划车辆、备注 | 保存 | 通过关联读取 |
| Token、路线选择、条件/奖励确认 | 保存 | 获取规划读取 |
| 职责定义及顺序 | — | 共用 |
| 自己的车辆职责、主力/备选/过渡、手工依赖 | — | 保存在各车队；修改需自己的玩家码 |
| 成员关联 | 独立稳定 ID | 入队/退出独立；界面不支持停用/排序 |

同一玩家可加入多个车队，个人数据共用，职责各自独立。服务器不会向持车队码的查看者返回玩家码。本机只显示已识别的自己的玩家码。

车辆与职责改动先存本地，随后手动上传。个人档与车队档分别比较版本；一次上传不是跨全部存档的大事务，部分失败保留已成功版本。同步期间阻止编辑/切换；刷新保护未上传内容；放弃本地版本需确认。切换存档保留缓存，读取新车队后需再次输入自己的玩家码。备份包含本机保存的存档码。

## 数据库部署记录

- 新环境先运行 `supabase/sql/004_aw_member_team_archives.sql`，再运行 `supabase/sql/005_aw_self_membership.sql`；两个脚本均可重复执行。它们不导入车辆资料。
- 本轮迁移：`supabase/migrations/20261003165512_aw_self_membership.sql`，对应线上 migration history `20261003165512 / aw_self_membership`，内容与 005 相同。当前 migrations 不是从零恢复整个项目的历史集；新环境按前述空表/接口脚本安装。
- 005 只替换函数，不改表或已有记录。新增私有校验层，公开 `aw_archive` 委托它，再复用 004 的数据校验、版本锁和存档写入。
- 三张存档表启用 RLS，撤销 anon/authenticated 的直接表权限；两层私有函数均撤销直接调用权限，固定空 `search_path`。只开放受码验证的公开 RPC；玩家码只存 SHA-256 哈希。
- 已检查安全 advisors；存档相关提示是持码匿名 RPC 的 SECURITY DEFINER，以及私有表 RLS 无直接策略。设计说明：[匿名 definer](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable)、[authenticated definer](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)、[RLS 无策略](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)。没有开放直接表策略。
- 部署及 SQL 合成测试前后，已有 **1 个玩家档、1 个车队档、1 条关联**的记录校验值一致；公共车辆仍 298 条。未改旧 `coop_profiles / game_states / aw_fleet_plan_items` 或车辆资料。
