# Token 规划实现记录 · 2026.10.04.4

对应 PR #8，基于 `b92ee09`。本页记录本轮实现，PR 更新以独立评论追加，不改旧评论或历史正文。

## 旧实现的问题

`fleet.memberPlan` 以手填 `s.tokens` 为起点，主要遍历已分配主力/备选的计划路线；奖励依赖 `confirmedRewards`，拥有车辆的奖励跳过，未体现来源车满经验/领取、实际解锁消耗和规划外来源。因此无法从已拥有、正在规划的具体车辆算出每种 Token 的需求和收益，手填余额也不能解释来源。按遍历顺序扣款可能错过先解锁来源车再回收奖励的顺序。

## 存档与边界

个人 AW-M 的 `assets[vehicleId]` 新增以下嵌套字段，职责仍只保存在 AW-T。`archives.personal/memberInto` 保留资产附加字段，重新绑定身份、跨队读取和备份不会丢失。

| 字段 | 含义 |
| --- | --- |
| `tokenRewards[rewardId]` | `unearned / ready / claimed`；缺值为未记录，不能假定已领取 |
| `tokenAcquisition` | `unknown / token / other`，已经发生的解锁方式 |
| `tokenUnlockPathId` | 实际已支付 Token 的完整路线，和未来 `routes` 选择分开 |
| `tokenSupply` | 主动加入的补充来源车；可独立于职责成为练车目标 |

三种奖励状态描述来源车辆的进度；`ready/claimed` 仅允许已拥有车辆。每个奖励 ID 一次。实际 Token 解锁必须属于该车辆，路线完整、存在 Token 消耗、数量非负整数且资料已核实。旧资产缺字段时提示补录，不根据拥有状态、历史确认开关或旧手填数量迁移成领取记录。改变实际记录会重新计算账目；它是用户对已发生行为的记录，不执行游戏内交易。

新字段仍位于既有 `assets` 内，RPC 顶层白名单不变；无 SQL 迁移。旧 `tokens` 和 `confirmedRewards` 保留，计算和 UI 不再读它们作余额/领取依据。删除车辆会删除其个人记录，因此移除已领取或已消耗的车前应保存备份并核对 Token 记录。

本地资料保持原样：6 类 Token、27 条来源奖励、23 条含 Token 的获取路线。本轮不扩充推测性来源，不修改车辆数据库。具体匹配使用 `vehicle_token_rewards.token_id` 和 `unlock_requirements.token_id`，不靠名称或等级猜测通用 Token。公开规则参考：[官方 Token 系统说明](https://armoredwarfare.com/en/news/general/introducing-tier-9-token-system)；历史规则不能替代资料中具体车辆的核实状态。

## 计算接口与顺序

- `token-plan.rewards/setReward/setUnlock/pathCards` 提供进度、已发生解锁记录的校验和 UI 条件卡片。
- `fleet.planningTargets` 合并职责目标与明确登记的计划车辆；`memberPlan` 合并路线节点后调用 `token-plan.build`。同一车跨职责、共享前置、共享来源不会重复计算。单目标视图仍包含主动选中的 `tokenSupply`。
- 已拥有节点终止前置递归，实际已记录解锁也不重复要求获取前置或支付未来消耗。显示关系仍不是解锁依据。
- 每类账目：已记录领取 − 实际消耗 = 当前可用；当前可用 + 本轮奖励上限 − 未来成本 = 理论最终余量。未知领取记录不算当前可用；未知数量单列来源条数，不猜数量。
- 当前可获得量来自实际排出的顺序。先领取/练满已拥有来源，再寻找前置已获得且余额足够的解锁，随后才加入该车的满经验奖励。路线/成本未知的节点不能产生可执行获取或提前贡献奖励。
- 优先来源车及其前置；竞争 Token 时回溯，按剩余节点集合缓存失败状态，免费获取可以交换顺序。最多 3000 次搜索，超限保留最大已确认部分并显示待确认，不宣称无解。受阻节点显示具体车辆、原因和下一步 Token 缺口。
- 支付规则是余额 `>=` 成本。用户原先要求的总量严格大于成本保留为单独 `bufferOk/reserveShortfall`；等量能够支付，但未通过余量检查。`executable` 需资料/记录完整、过程可支付、无受阻及余量规则通过。

规划奖励是“获取后练满经验”的上限，不能等同于当前持有，也不能拿来支付更早的解锁。补充来源展示全部已采集候选；只有主动加入后才把它的获取成本、前置和收益加入规划。

## 同步实现

`store.saveAndSync` 先完成本地存储，再自动上传个人档和车队改动；`saveSharedRoles` 使用同一流程。UI 所有个人/职责保存路径已接入。低层 `save` 保留给本地身份建立和事务式操作，新的无码个人档不在用户未生成码时自动发布。

`store.refresh` 串行上传待同步内容，成功后才读取车队，或在只有个人码时读取个人档。上传/版本冲突失败停止后续读取；部分成功保留新版本号和余下 dirty 标记。没有未上传内容时 `refreshIfClean` 可在返回页面读取；打开表单/车辆草稿时页面不会自动读取，编辑层重试仅上传，不下载覆盖草稿。同步期间拒绝写入与切换；状态和错误通过 `syncInfo` 常驻展示。

职责还是共享定义，自己的车辆安排仍自我权限限制。没有修改 RPC 权限、RLS、密钥或服务端整队保存约束。

## 2026.10.04.6 前置配置实现

配置在个人资产 `prerequisites` 中保存，不增加顶层存档字段或修改数据库结构：`mode` 为 `ignore / known / custom`，`pathId` 指向已有解锁路线，`customVehicleIds` 保存临时前置车辆，`tokenSourceVehicleIds` 保存本路线对应 Token 的已选来源车。个人存档投影保留整个明确登记资产；派生车队职责仍使用 `source: tech_tree`，不上传为手工职责。已有 `routes` 选择继续读取，新配置保存时替换对应旧路线键。

`fleet.saveAsset` 为新计划保存 ignore。`fleet.resolveRoute` 在忽略模式只保留目标，不展开源车辆，并明确标记 `ignored`；已知模式按实际 requirement 展开，自定义模式只替换来源车辆关系，保留 Token 和其他已知条件。`setPrerequisites` 校验车辆、来源 Token 匹配、去重与循环，在副本检查通过后才保存。`memberPlan` 合并节点，`token-plan.build` 对 ignored 节点阻止免费获取和奖励预测，仍计算单一已知路线中的真实 Token 需求；不把未知多路线猜成某种消耗。

`aw-prerequisites` 编辑层使用独立草稿：第一层已知路线/来源，第二层明确进入自定义后才搜索全部车辆。取消不写入，保存复查个人权限，再复用 `saveAndSync`；打开期间 hold 资料更新，保存/取消/销毁 release。页面 onShow 不在编辑期间读取云端。临时关系随个人码在设备间恢复，公共目录及其核验状态完全独立。

本版 80 项回归含默认忽略、忽略后派生职责清理、旧路线兼容、匹配来源、去重、自定义/循环、取消、权限及真实存档接口的双设备模拟同步；没有执行真实数据库事务或修改线上资料服务。
