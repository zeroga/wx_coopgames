# 微信合作游戏小程序 / wx_coopgames

用于管理合作游戏资料、团队计划与共享进度的微信小程序项目。

当前项目首先覆盖 **SnowRunner**，并正在加入 **Armored Warfare（AW）车辆资料库与团队车辆计划**。后续可继续扩展其他需要多人共享进度、车辆/装备计划或资料查询的游戏。

## 当前基准

小程序端当前以以下版本作为代码基准：

- **提交审核版：`coopgame-review-v3-collapse-full.zip`**
- 日期：2026-10-01
- 后续小程序修改均应从该版本进入 Git，不再以聊天附件或临时 ZIP 作为正式版本来源。

数据库当前使用 Supabase 项目：

- 项目名：`wx_coopgame`
- Git 仓库：`zeroga/wx_coopgames`

> Git 是项目代码、数据库结构变更和可维护数据文件的版本基准。  
> Supabase 是实际运行数据库，不应再通过大量不可追溯的临时 SQL 作为长期维护方式。

## 版本、体验版与正式审核

微信小程序正式发布需要人工审核。维护者会在审核通过后才合并对应 PR；审核期间 PR 保持开放，不提前合并 `main`。

- **体验版对应最新 PR 的代码**，当前 AW 为 PR #8、分支 `feat/aw-catalog-fleet-v1`。拉取此分支重新编译，当前测试版为 `2026.10.04.5`，上传版本号 `0.1.0-test.20261004.5`。
- Git 推送不会自动上传微信体验版：维护者仍需用微信开发者工具上传，并在微信后台设为体验版。`main` 对应已完成审核并合并的代码，不能用它判断最新体验版本。
- PR Conversation 采用**每次追加新 comment**记录版本、具体实现与验证结果，不覆盖历史 comment，也不把 PR 正文反复改成最新版本。实现问题应能追到对应 commit 和当次记录。
- Issue 正文可更新为当前需求或核验清单，不要求保留每次编辑的全文。

AW 资料与小程序代码分别发布：客户端内置初始资料包，自动检查自有 Supabase 资料发布服务，校验后缓存新资料；离线继续使用已缓存或随包资料。资料更新不改玩家/车队存档。当前为发布经过核验的目录包，不是让手机直连逐表查询或自动采集未核实数据。详细发布流程见 [AW 线上资料更新](docs/aw/catalog-updates.md)。

## 功能范围

### SnowRunner

现有小程序主要提供：

- PC / 主机双页签
- 双成员团队资料
- 团队码共享合作档
- 赛季与区域推进清单
- 目标勾选、编辑、增删
- 车辆取得与成员分配
- 顺序调整
- S1–S19 赛季数据
- 本体区域独立记录
- 云端共享状态

团队数据模型同时作为 AW 团队车辆计划的基础。

### Armored Warfare

AW 模块目标包括：

- 浏览车辆资料
- 按等级、车型、经销商、国家等基础条件筛选
- 按 ERA、烟幕、步兵班等车辆能力筛选
- 按自导导弹、攻顶导弹等弹药能力筛选
- 按 AP 穿深筛选
- 查看车辆主要武器与弹药
- 查看可研发配件
- 查看完整科技树
- 查看车辆研发 / Token 解锁条件
- 使用现有团队码共享车辆计划
- 查看其他成员已经计划的车辆
- 后续扩展为车队组建器

AW 第一版不使用车辆图片作为核心数据依赖，也暂不加入主观评分。

AW 入口提供“车辆资料库、车队管理”两张模块卡片，科技树从车辆详情和获取规划进入。车辆资料只读取随包本地资源。顶部车辆信息和车队状态常驻，其余模块独立折叠；展开武器模块后列出全部武器，每枚弹药收起为一行并可单独展开详情。自己的车辆登记使用职责标签。成员使用独立 `AW-M-` 存档码，车队使用 `AW-T-` 码读取团队。随后输入自己的玩家码识别身份，未入队先确认，已入队直接读取并显示退出；只能修改自己的车辆与职责。

Issue #3 / #5 的小程序交互测试版入口、运行步骤、改动记录与数据库过渡说明见 [AW 本地测试说明](docs/aw/miniprogram-v1-testing.md)。

## 数据与版本管理原则

### 小程序代码

小程序源码直接进入本仓库。

正式基准由 Git commit 确定，不再依赖“最新版 ZIP”作为长期版本判断方式。

### Supabase Schema

数据库结构变更应进入：

```
supabase/migrations/
```

长期规则：

1. 先形成可审查的 migration。
2. 再应用到 Supabase。
3. 应用后验证实际数据库状态。
4. Git 与线上 migration history 保持对应。

临时诊断 SQL 可以直接执行，但永久结构修改不能只存在于一次聊天任务中。

### AW 数据

AW 车辆、武器、弹药、科技树与解锁资料需要长期维护。

原则上：

- 原始 / 可维护数据应进入 Git。
- Supabase 作为运行时查询数据库。
- 单车修正应能通过 Git diff 追溯。
- “未采集到”不能被解释成“游戏中不存在”。
- 无法公开确认的数据保持未知或待游戏内核实，不猜测补全。

不通过 migration 或部署任务自动导入资料；已有正式库无需重新初始化。

## 安全要求

本仓库为公开仓库。

禁止提交：

- Supabase `service_role` / secret key
- 私有数据库密码
- 微信平台私钥
- 用户真实团队码
- 其他访问令牌或账号密钥

前端只能使用适合公开客户端使用的配置，并依赖数据库端 RLS / RPC 做实际访问控制。
